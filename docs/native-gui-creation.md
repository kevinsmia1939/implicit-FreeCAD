# GUI creation and background defaults

Select a primitive native gyroid and a conventional Part box, then run the mixed
Common or BoxMinusField command. The creation task stages operation, seam
tolerance, tracing budget, corner handling and optional operand hiding before
creating a document owner. Defaults are 0.1 mm, 512 cells and Regularized corner
handling, which supports the qualified 10 mm zero-gyroid cube.

OK starts a private native boundary job. Cancel, changed controls, dirty operands,
lost documents or unrelated transactions discard the request. A failed build
keeps the task open for correction. There is no provisional feature or open
creation transaction during numerical tracing. Successful publication creates
the source and changes operand visibility together in one undo transaction.
Transient Part mesh/cache changes do not invalidate unchanged mathematical inputs;
the submitted original B-Rep record remains the exact worker descriptor.

Select the resulting boundary and use the native-solid creation command. Its
existing staged worker build creates a validated native solid when supported.
Both GUI-created owners now have BackgroundRecompute=true. Ordinary edits to
their field/box/source parameters therefore use the guarded source-to-solid
worker pipeline without manually enabling flags. Source-only boundaries still
do not claim native-solid validation.

GUI solid creation preserves the policy of an existing source. Old documents
with false flags and synchronous console factories are unchanged. Set a legacy
source's BackgroundRecompute property explicitly to adopt background source
tracing. The new flags are persisted; save/reopen restores topology and policy
without automatically recertifying stored geometric proof flags.

The basic Add Gyroid command still creates the compiled field primitive. Everyday
native-solid primitive exposure, tree pending/failure feedback, broader input
families, curved B-Rep operands, snapping/history and cross-workbench consumers
remain Stage 2–4 work. Serialization, cap display, result conversion and Coin upload
remain GUI-thread work. The kernel's 0.1 mm and degeneracy policies are unchanged.
